# 教育产品前端：无头组件库选型简报（给 Agent 独立判断用）

> 用途：整段交给任意 AI / 工程 Agent。本文 **只描述背景、动机与必须满足的需求**，**不指定**具体库（不预设 React Aria / Base UI / Radix / Ark 等）。  
> 请阅读后自行调研、对比、给出选型结论与理由；可推荐 1 个首选 + 1 个备选，并说明取舍。  
> 决策人：Joe（UI 设计师，无工程背景）；落地施工：AI Agent。  
> 产品语境：Big Academy Writing 等 K12 教育软件（PC + 平板/移动端）。

---

## 1. 角色与工作方式（约束施工，不约束库名）

| 角色 | 负责 | 不负责 |
|---|---|---|
| **设计师（Joe）** | 视觉、交互细节、动画与体验标准、验收 | 写生产代码；自行实现底层交互语义 |
| **AI Agent** | 调研选型、按选定库施工、把设计样式/动效套上去 | 用「看起来像」的裸 DOM 冒充可访问交互；擅自绑架视觉成某套 UI 皮肤 |

要点：设计师 **不懂前端代码**，依赖 AI 施工；但对 **样式、交互细节、动画、使用体验** 要求高。选型必须让「设计师锁体验 + AI 稳定落地」成立。

---

## 2. 真实动机（表象 vs 实际在买什么）

表面在问「选哪个开源无头组件库」。实际要买的是一份 **合作契约**，不是某个品牌名：

1. **把「行为正确」从设计师身上卸掉**  
   强项：视觉 / 交互细节 / 动效 / 体验。弱项：工程实现。  
   担心：AI 用裸控件拼出「演示好看、键盘/触控/焦点一碰就穿帮」的界面。  
   → 需要成熟的 **行为与无障碍层**；设计师只锁外观与动效，不自己发明焦点陷阱、弹层关闭、键盘操作等语义。

2. **教育产品隐性标准（教室场景 ≠ 设计评审场景）**  
   - 课中答题、学习路径等真实使用  
   - 触控与平板（含横屏）  
   - 无障碍（读屏、焦点、键盘）  
   - **国际化**（中英等 locale；数字 / 日期 / 阅读顺序可随语言）  
   → 方案必须经得起教室，不只要经得起 demo。

3. **跟 AI 分工清晰**  
   需要共同语言：说到选项、Tab、弹层、表单，有可对稿的标准零件与文档，避免每次从零发明交互。  
   「对 AI agent 友好」= 文档结构清晰、API 稳定可预测、有足够示例 / 机器可读文档，便于 Agent 少幻觉。

4. **可控高保真，拒绝模板脸**  
   外观、品牌色、圆角、动效曲线全听设计。  
   → **必须无头（或等价可完全换皮）**；不要开箱即长得像 Ant / MUI / Chakra 的整包皮肤库作为默认。

5. **一次选对、少返工**  
   长期产品骨架优先于「明天出一版可丢弃演示」。  
   可接受施工稍慢，不可接受后期为无障碍 / 触控 / 复杂表单 / i18n 推倒重来。  
   （若方案区分「正式骨架」与「24h 可丢弃抛型」，须写清边界，且抛型不得污染正式约定。）

---

## 3. 必须满足的需求（验收标准）

| 需求 | 落成要求 |
|---|---|
| 我控视觉与动效 | 无头或不绑设计语言；动效用 CSS / Motion 等叠在行为层外 |
| AI 能稳定落地 | 文档/类型/示例足以支撑不懂代码的设计师 + Agent 协作 |
| PC + 移动/平板 | 指针与触控都可用；主流程在平板横屏场景可完成 |
| 课中教育场景 | 表单、选择、导航、反馈、进度等常见模式有稳妥零件或清晰组合方式 |
| 无障碍 | 键盘可走主流程；焦点管理合理；读屏有语义；勿默默用不可访问自定义行为 |
| 国际化 | 中英等单语切换（同一时刻不中英叠字）；locale 相关能力（含数字/日期等）有正路，禁止后期硬拼半套 |
| 组件尽量丰富 | 覆盖教育软件常见：表单控件、对话框/弹出层、Tabs、菜单、列表/表格/树、数字与日期类输入、进度/反馈等——不足处须明示 gap |
| 开源 | 许可证适合商用产品（如 MIT 等宽松许可优先） |

**教育产品隐性标准四条：教室可用 · 触控/平板 · 无障碍 · 国际化。**

---

## 4. 明确不做 / 反模式

- 默认采用整包有皮肤 UI，导致产品长得像某设计系统模板。  
- 用不可访问的自定义交互冒充「已经有组件库」。  
- 只优化桌面鼠标，忽略触控与平板。  
- 只做中文或英文硬编码，把 i18n 留到「以后再说」。  
- 为了快，把可丢弃抛型的技术债写进正式产品骨架且不声明。

---

## 5. 请 Agent 独立完成的输出

请 **自行调研** 当前主流开源无头（或无头优先）方案并给出：

1. **候选对比表**（至少 3 个）：覆盖程度、A11y、移动/触控、i18n、文档/AI 友好度、维护活跃度、与「设计师控皮 + Agent 施工」的匹配度。  
2. **首选 + 理由**（必须逐条回扣 §2 动机与 §3 需求，尤其隐性四条）。  
3. **备选 + 在什么情况下改选它**。  
4. **已知 gap**：教育场景下库覆盖不到、需要自研或加插件的部分。  
5. **给设计师的一句话**：不讲黑话，说明「你负责什么 / Agent 负责什么 / 库负责什么」。

**禁止**：在未对比的情况下直接宣布某一库为唯一答案；禁止忽略国际化与无障碍。

## 6. 一句话备忘（给所有 Agent）

> 用户不是在追某个库名，而是在找：**我画体验、AI 施工、行为别翻车**——且必须扛住教育产品的教室、触控、无障碍与国际化。库名由你论证后给出。
